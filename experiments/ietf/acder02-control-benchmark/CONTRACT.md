# Exact shared contract

Use EVIDENCE_SCHEMA.json and PROFILE.json. The JSON schema deliberately accepts structurally incomplete native payloads inside an intact envelope: malformed native observations are test inputs, not rejected author-file syntax. Native payload fields are listed in PROFILE.json and development cases. Hash payload_utf8.encode("utf-8") exactly, then parse JSON. Every claim scope is explicit in its query and must remain attached to output.

For C, obligations are sorted by instruction_id then target_id, with fields instruction_id,target_id,disposition. Instruction accounting has total,with_obligations,terminal_empty,all_excluded,target_resolution_unclosed. Expected manifest-only instructions with missing metadata belong to target_resolution_unclosed. obligation_counts has total and every uppercase disposition key, including zeroes. receiver_record_counts has total and the lowercase disjoint classes substitution,conflict,invalid,duplicate,matched,orphan. Structural result is PASS/FAIL/INCONCLUSIVE. aggregate_claim exposes fact,scope,qualification,conditions in the same output as structural_result; its assertion is the structural result, not end-to-end delivery. Oracle reconciliation uses the same count representation and exposes expected aggregate qualification/conditions, but prose reasons are not scoring labels.

An explicit query scope contains cutoff/clock_id and, as relevant, target_id/boundary_id/operation_id/predicate_id/window/before_record_id/after_record_id/transformation_record_id. `subject` contains instruction_id (or instruction_ids for population claims) and record_ids for integrity claims. Claim ID is an opaque row identifier. Evidence refs use record:<record_id> or input:<field-path>. Oracle fields justified_state,qualification,conditions are scored; rationale, draft_clauses, evidence_basis, missing_evidence and known_nonclaims document the author's independent derivation. A separate latent_truth_ref points to latent_truth.json#/<claim_id> and does not supply the epistemic state.

An author-side signature is an optional envelope.signature object with algorithm,public_key_pem,signature_hex. Verification metadata stays in the author case directory. No evaluator reads it. Such a signature is a synthetic fixture integrity fact, not external authority.
