# K1: frozen synthetic control-failure benchmark protocol

This is the new 24-case K1 benchmark, distinct from the frozen prior 14-case/15-run pilot. It is a same-owner synthetic comparison of three analytical implementations, not external review, an independent product comparison, deployment evidence, safety improvement, or adoption. The author prepares the independent data and oracle without evaluator output; the evaluator is written by the parent task. Protocol, profile, selection and metric commitments precede evaluator implementation. This author package contains no evaluator.

## Source and protocol boundary

SOURCE_PINS.json pins exact IETF -02 bytes, URL and retrieval time, public main base, plan and earlier-study lineage. Only the pinned draft clauses, new user request and the agreed profile inform case authoring. No B1 private/oracle files, B2 results, B3 comparison outputs or previous 15 expected results were opened for this design. The supplied user request itself mentions prior pilot outcomes; this exposure is disclosed and is not used as a new case oracle. The official source copy, not a newer revision, is normative background. PROFILE.json defines the narrower experimental choices and is not a new protocol or standard amendment.

## Freeze and first measurement

There are exactly 12 development and 12 holdout cases, one of each per the twelve preselected categories in SCENARIO_SELECTION.json. Development evidence and oracle may inform implementation. Holdout evidence, latent truth and oracle remain under holdout/ and are not disclosed to the evaluator author before a recorded logic-freeze commit. The first protocol commit fixes contracts, selection and metrics before implementation. A second author commit fixes all 24 case/oracle bytes before any comparator execution or measurement. No comparator output can be used to select cases or tune the oracle; this two-stage sequencing was agreed before implementation. The final author manifest pins both stages. A holdout manifest exposes only relative paths, byte lengths and hashes until logic freeze. First holdout evaluation must use the frozen evaluator commit and these frozen bytes; retain that first output even if bugs are later diagnosed. Do not tune comparator, oracle, case selection or conditions after holdout. Any correction is a new version with the original preserved, never a silent repair. This is same-owner withholding, not independence or a blinded third-party review.

## Inputs and oracle independence

Each case has evidence.json, latent_truth.json and oracle.json. Evaluators may consume only evidence.json and shared PROFILE.json; latent truth and oracle are scoring/author artifacts, never evaluator inputs. Evidence consists of frozen population declarations, instruction metadata, byte-bound native observations, and explicit requested scoped queries. It contains no expected final state, case category or split. Query IDs are labels only, not decisions. Claim states distinguish SUPPORTED, REFUTED, INDETERMINATE, NOT_EVALUATED and NOT_APPLICABLE. Qualification and conditions remain separate. An independently reportable receiver fact can be supported despite a missing issuer observation and an INDETERMINATE delivery obligation.

Oracle justified states are authored claim by claim from a cited draft clause, the observable evidence and the frozen experimental profile. They are not derived from B2 or the evaluator. Each oracle cites evidence present, absent predicates, known nonclaims and a rationale. A separate latent truth file specifies synthetic events and bool/null proposition values. A true latent event without sufficient exposed evidence is not a supported claim. Accepted evidence does not itself promise ground truth beyond its stated predicates. Positive false assertions and epistemic overclaims are different metrics. No bare absence becomes a negative observation. Oracle ambiguity is an explicit flag, not an inferred evaluator error.

## Comparators and applicability

PROFILE.json freezes the exact three contracts. Integrity-only verifies actual SHA256 of supplied UTF-8 envelope payload bytes and asserts only byte integrity; it does not verify signer identity, signatures or authority. The explicitly naive ACK comparator promotes successful ACKs to receiver receipt, all-required delivery, enforcement and effect, using the declared intentionally weak rule. It does not claim execution, ordering, population completeness, mediation or semantic preservation. ACDER-bounded preserves the scoped evidence dimensions, obligation/accounting model, structural result and same-context aggregate qualification in this profile. Applicability is fixed by comparator and query kind before seeing results. A comparator cannot hide mistakes by returning NOT_APPLICABLE for a kind its contract covers. Category 7 includes a genuine local synthetic-key Ed25519 signature with author-side OpenSSL verification; evaluators remain digest-only and make no signature-verification claim. A valid signature still supplies no missing enforcement or effect evidence.

## Frozen metrics

Every metric publishes numerator, denominator and rate by comparator, claim kind, development/holdout/total; zero denominator is null. Primary evidence scoring excludes only explicitly ambiguous claims and retains all other claims in the case. Every claim remains in transparent all-row output with applicability and ambiguity flags. No aggregate/claim exclusion inherited from the previous pilot applies here. Integrity is a separate bounded class; no integrity result is relabeled as an effect claim.

* Unsupported stronger support: predicted SUPPORTED with oracle not SUPPORTED, divided by applicable, unambiguous, non-integrity oracle-not-SUPPORTED queries. Report unsupported-but-latently-true assertions separately.
* Semantic incorrectness: definite prediction (SUPPORTED=true or REFUTED=false) contradicting available bool latent truth, divided by applicable, unambiguous definite predictions with available bool truth. INDETERMINATE is not a semantic false prediction. This is correctness within an authored synthetic world only.
* False rejection: predicted REFUTED where oracle SUPPORTED, divided by applicable, unambiguous oracle-SUPPORTED queries.
* Useful-support recall: predicted SUPPORTED where oracle SUPPORTED / applicable unambiguous oracle-SUPPORTED. Also count supported claims withheld as INDETERMINATE/NOT_EVALUATED separately.
* Appropriate withholding: predicted INDETERMINATE or NOT_EVALUATED where oracle is INDETERMINATE or NOT_EVALUATED / applicable unambiguous oracle-INDETERMINATE-or-NOT_EVALUATED.
* State agreement and fixed confusion matrix: applicable unambiguous evidence-oracle rows, with all five states retained; unexpected NOT_APPLICABLE is an error, not denominator removal.
* Qualification agreement and exact condition retention: applicable unambiguous rows; compare qualification and sorted unique condition sets independently of the state label. Text reasons and evidence-reference wording are inspectable but are not arbitrary exact-string scores.

Report applicability counts, indeterminate and not-evaluated counts, and all per-target structural/count mismatches separately. The small fixed synthetic set has no confidence intervals, statistical significance, prevalence estimates or generalization. It is intentionally adversarial, not representative production traffic. Distinguishing results apply only to the explicit claims these analytical comparators make. If there is no distinguishing result, report NO DIFFERENTIATING RESULT/HOLD without adding favorable cases.

## Validation and reporting

Author validation checks JSON schemas, source hashes, per-case references, oracle/latent separation, signature verification, counts and immutable manifest hashes. It must not execute an evaluator or regenerate oracle states from a rule implementation. Evaluator validation later includes deterministic case tests and mutations for target substitution, missing receiver and missing effect evidence, plus signature-to-execution and no-ACK-to-no-delivery negative checks. One-command replay, exact version/commands/environment/run record, results and limitations belong to the evaluator package. No public push, PR, release, issue, disclosure or standard submission is authorized by this protocol.
